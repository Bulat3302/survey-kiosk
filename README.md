# Опрос-стойка: опрос на экране + QR-код для телефонов

Стойка из двух половин, всё в браузере:

- **слева** — опрос сразу на экране (наша копия, встроенная в страницу; ответы автоматически уходят в настоящую форму платформы);
- **справа** — QR-код на официальный опрос, чтобы участники могли пройти его и со своего телефона.

После отправки ответа форма сама сбрасывается к пустой — и следующий участник может проходить сразу.

**Развёртывание на сервере через MobaXterm — пошагово в [DEPLOY.md](DEPLOY.md).**

Стек: чистый HTML/CSS/JS, зависимостей в рантайме нет (QR-библиотека вендорена в `js/lib/`). Раздаётся nginx в Docker.

## Быстрый старт

```bash
docker compose up -d --build
```

Откройте <http://localhost:8080>.

Остановить: `docker compose down`. Перезапустить с изменениями: `docker compose up -d --build`.

## Как работает стойка

1. Откройте сайт на компьютере-стойке и разверните окно браузера на весь экран (F11).
2. Слева сразу виден опрос (наша копия, встроенная в страницу), справа — QR-код. Ничего нажимать не нужно.
3. Участник заполняет опрос: вопросы подтягиваются из платформы автоматически (`GET /api/form`), поэтому копия всегда повторяет настоящую форму.
4. После отправки ответы уходят в настоящую форму платформы (`POST /api/form-submit` → платформенный `complete`), копия ответа сохраняется и у нас в `data/answers.jsonl`, а форма сбрасывается к пустой для следующего участника.

QR-код ведёт на официальную страницу опроса платформы — прохождение с телефона работает как обычно, ответы попадают в платформу (и к нам, если вебхук-интеграция принята).

## Страница настроек (/setting/)

Адрес: `http://<адрес-стойки>:8080/setting/`. Доступ по токену `ADMIN_TOKEN` из `.env` (страница на публичном IP, поэтому без пароля не открывается).

На странице видно:

- сколько ответов получено и когда был последний;
- название и ссылку текущей формы.

Чтобы сменить форму: вставьте новую ссылку (прямую или короткую) и нажмите «Проверить и применить». Система извлечёт идентификатор формы, проверит её на платформе и при успехе переключит и опрос на стойке, и QR-код. После смены достаточно обновить стойку (Ctrl+F5). Настройка хранится в `data/config.json` и переживает пересборки.

## Поддерживаемые типы вопросов

Наша страница строит поля по определению формы, которое каждый раз забирается с платформы. Поддерживаются:

| Тип на платформе | Как выглядит у нас |
|---|---|
| `text` | многострочное поле (с лимитом символов) |
| `number` | однострочное поле |
| `date` | одно поле или диапазон «с/по», плюс время, если форма его требует |
| `one_choice` | переключатели, плюс «Другое», если разрешено |
| `multiple_choice` | флажки, плюс «Другое» (эксклюзивный вариант) |
| `scale` | ряд кнопок с вариантами оценки |

**Вложения к вопросам** тоже поддерживаются: если к вопросу прикреплена картинка (`file_type: "media"`), она показывается прямо под текстом вопроса; если документ (`file_type: "document"`) — выводится ссылка на скачивание. Картинки у вариантов ответа (`choices[].image`) отображаются под текстом варианта.

Поэтому изменения на платформе — новые вопросы этих типов, правка текстов и подсказок, обязательность, порядок, лимиты символов, формат дат, прикреплённые картинки и файлы — подхватываются автоматически: достаточно обновить страницу стойки (Ctrl+F5).

**Не поддерживаются** (страница покажет заметку вместо поля): загрузка файла в ответе (тип `file`), сопоставление, последовательность, условные вопросы (`condition`). Если в форме появятся такие типы — их нужно добавить в `survey.html`, либо участники проходят такой опрос с телефона по QR-коду.

Если нужна **другая форма** — поменяйте её на странице настроек `/setting/` (см. выше): вставьте новую ссылку, система проверит её и переключит и опрос, и QR-код. Вручную править файлы не нужно.

## Как подключить свой опрос

Вся настройка — в одном месте, в файле **`js/config.js`**:

```js
var SURVEY_URL = "https://forms.hr.alabuga.digital/forms/ffca186d-804c-4245-874c-434581a59d96/pass";
```

Эта ссылка попадает в QR-код и в обе кнопки открытия опроса. Подойдёт полная ссылка (https://…) или относительный путь к своей странице. После правки пересоберите контейнер:

```bash
docker compose up -d --build
```

После любых правок `css/js` обновите версию ассетов в `index.html` (параметр `?v=` в подключениях стилей и скриптов) — иначе браузеры могут отдавать закэшированную старую версию страницы.

## Интеграция: приём ответов (вебхук)

Сервис опросов умеет присылать заполненные анкеты на наш адрес. В форме интеграции на их стороне укажите:

- **Название** — любое, например «Стойка опроса»;
- **URL** — `http://<IP-или-имя-компьютера-стойки>:8080/api/answers` — адрес, по которому сервис опросов достучится до стойки в своей сети;
- **API ключ** — значение `API_KEY` из файла `.env` (создайте его из образца: `cp .env.example .env` и впишите свой ключ).

Приёмник проверяет ключ: подойдёт заголовок `X-API-Key`, `Authorization: Bearer …`, параметр `?key=…` или поля `key` / `api_key` в теле запроса. Принятые анкеты дописываются по одной строке в `data/answers.jsonl`.

Проверка без сервиса опросов:

```bash
curl -X POST "http://localhost:8080/api/answers" \
  -H "X-API-Key: КЛЮЧ_ИЗ_COMPOSE" \
  -H "Content-Type: application/json" \
  -d '{"form": "тест"}'
cat data/answers.jsonl
```

С неверным ключом придёт ответ 401. Накопленные ответы можно посмотреть: `GET /api/answers` с тем же ключом. Сменить ключ: поменяйте `API_KEY` в файле `.env` и выполните `docker compose up -d`.

Важно: сервер опросов должен иметь сетевой доступ к порту 8080 компьютера-стойки.

## Порт

По умолчанию сайт на порту **8080** хоста (см. `docker-compose.yml`). Чтобы поменять, отредактируйте строку `"8080:80"` — формат `"<порт-хоста>:80"`.

## Автовозврат и счётчик ответов

Ответы из нашей копии опроса сохраняются на сервере сразу при отправке (`data/answers.jsonl`), а форма после экрана «Спасибо» сама сбрасывается к пустой — следующий участник проходит опрос без перезагрузки страницы. Под опросом виден счётчик «Ответов получено: N · последний: время».

Дополнительно сервис опросов может присылать анкеты вебхуком (`POST /api/answers`) — если интеграция принята; тогда к нам попадут и ответы, заполненные с телефонов по QR.

## Структура

```
index.html          — главный экран: опрос слева (iframe с копией), QR справа
survey.html         — копия опроса: вопросы из платформы, отправка в неё же
setting/index.html  — страница настроек: счётчик и смена формы (по токену)
js/config.js        — запасная ссылка на опрос (для QR, если сервер недоступен)
js/app.js           — QR-код и счётчик ответов
js/lib/qrcode.min.js — вендоренная библиотека QR-кодов
css/style.css       — стили экрана
nginx.conf          — статика + прокси /api/ на сервис
api/server.py       — приём ответов, прокси отправки в платформу, счётчики, /api/config
api/Dockerfile      — образ сервиса (python:3.11-slim)
data/answers.jsonl  — принятые анкеты (появляется после первого ответа)
data/config.json    — выбранная форма (создаётся при смене через /setting/)
Dockerfile          — nginx:alpine + статика
docker-compose.yml  — оба сервиса, порт 8080, ключи из .env
```
