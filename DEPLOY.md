# Развёртывание на сервере (Linux) через MobaXterm

Всё работает в браузере, без десктоп-приложений. Архитектура:

- **Сервер (Linux)** — Docker-стек: страница стойки (nginx) + приём ответов по вебхуку (Python) на порту 8080.
- **Компьютер-стойка** — обычный браузер (Chrome/Edge) в полноэкранном режиме открывает `http://<адрес-сервера>:8080`.
- **Телефоны участников** — сканируют QR и попадают напрямую на опрос (нужен доступ телефона к сайту опроса — интернет или сеть, где опрос доступен).
- **Сервис опросов** — присылает заполненные анкеты вебхуком на `http://<адрес-сервера>:8080/api/answers`.

## Шаг 1. Подключение к серверу и установка Docker

1. MobaXterm → Session → SSH → укажите адрес сервера, порт (обычно 22) и пользователя → OK.
2. Обновите систему и установите Docker:

```bash
sudo apt update && sudo apt install -y ca-certificates curl
curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
```

3. Выйдите и зайдите по SSH заново (чтобы применилась группа docker), проверьте:

```bash
docker --version && docker compose version
```

### Важно: доступ к Docker Hub

При сборке у нас выяснилось, что Docker Hub из вашей сети недоступен (TLS-таймаут). Решение — одно из двух:

**а) зеркало реестра** (проще в перспективе):

```bash
sudo mkdir -p /etc/docker
echo '{"registry-mirrors": ["https://docker.1ms.run"]}' | sudo tee /etc/docker/daemon.json
sudo systemctl restart docker
```

(Если зеркало `docker.1ms.run` в вашей сети не отвечает — подставьте другое доступное, например `docker.xuanyuan.me` или зеркало вашей организации.)

**б) перенести готовые образы** (они уже скачаны на рабочей Windows-машине):

```bash
# на Windows (PowerShell или CMD):
docker save nginx:alpine python:3.11-slim -o docker-images.tar
```

Затем в MobaXterm перетащите `docker-images.tar` в левую SFTP-панель (загрузится на сервер) и выполните:

```bash
docker load -i ~/docker-images.tar
```

## Шаг 2. Загрузка проекта на сервер

В MobaXterm слева есть SFTP-панель (обзор файлов сервера). Создайте папку `survey-kiosk` и перетащите в неё из проводника Windows **только эти файлы**:

```
index.html
css/  (папка целиком)
js/   (папка целиком)
api/  (папка целиком)
nginx.conf
Dockerfile
docker-compose.yml
.dockerignore
.gitignore
```

**Не нужны на сервере:** `data/` (создастся сам), тестовые файлы.

Если проект у вас в git — просто `git clone <репозиторий>`.

## Шаг 3. Настройка перед запуском

```bash
cd ~/survey-kiosk
```

1. **Ссылка на опрос** — `nano js/config.js`, проверьте `SURVEY_URL` (уже прописан ваш опрос).
2. **API-ключ вебхука** — создайте файл `.env` из образца и впишите свой ключ (это пароль для приёма ответов):

```bash
cp .env.example .env
openssl rand -hex 24      # сгенерировать ключ
nano .env                 # вписать его в строку API_KEY=...
```

(Значение ключа впишите и в `.env`, и в форму интеграции у сервиса опросов — они должны совпадать.)

3. Порт по умолчанию 8080 — при желании меняется в `docker-compose.yml` (строка `"8080:80"`, формат `"<порт>:80"`).
4. **Папку данных создайте сами до первого запуска** — иначе её создаст Docker от имени root, и файлы ответов нельзя будет удалить без sudo:

```bash
mkdir -p ~/survey-kiosk/data
```

Контейнер приёмника работает от обычного пользователя (uid 1000), поэтому созданная вами папка и все будущие файлы ответов принадлежат вам.

## Шаг 4. Запуск и проверка на сервере

```bash
docker compose up -d --build
docker compose ps
```

Оба контейнера должны быть `healthy` (`survey-kiosk` и `survey-answers-api`). Проверки:

```bash
curl -s http://localhost:8080/ | head -n 5          # отдаётся страница стойки
curl -s http://localhost:8080/api/last              # {"ok": true, "ts": null, "count": 0}
```

## Шаг 5. Сеть и файрвол

Порт 8080 должен быть доступен:

- **с компьютера-стойки** (он в той же сети — обычно достаточно);
- **с сервиса опросов** (вебхук!). Если сервис опросов находится вне вашей сети — нужен проброс порта (NAT/порт-форвардинг) или публичный адрес; уточните у сетевых администраторов.

Если на сервере включён `ufw`:

```bash
sudo ufw allow 8080/tcp
```

## Шаг 6. Форма интеграции у сервиса опросов

| Поле | Значение |
|---|---|
| Название | любое, например «Стойка опроса» |
| URL | `http://<адрес-сервера>:8080/api/answers` |
| API ключ | значение `API_KEY` из файла `.env` |

Сервис будет присылать анкеты POST-запросом; наш приёмник принимает ключ из заголовка `X-API-Key`, `Authorization: Bearer`, параметра `?key=` или полей `key`/`api_key` в теле — подойдёт любой способ, которым сервис его передаёт.

## Шаг 7. Компьютер-стойка (браузер)

1. Chrome или Edge: откройте `http://<адрес-сервера>:8080`, нажмите F11 (полный экран).
2. **Разрешите всплывающие окна для этого сайта** (одноразово): Настройки → Конфиденциальность и безопасность → Всплывающие окна → добавить адрес в «Разрешено». Без этого кнопка не сможет открыть вкладку опроса.
3. Опрос уже встроен в левую половину страницы (наша копия, вопросы подтягиваются из платформы). После отправки ответы уходят в настоящую форму платформы, копия сохраняется на сервере, а форма сбрасывается к пустой для следующего участника.
4. Телефоны: участники сканируют QR и попадают на официальный опрос напрямую (ответы попадают в платформу; к нам — если вебхук-интеграция принята).

## Шаг 8. Проверка приёма ответов

```bash
curl -X POST "http://<адрес-сервера>:8080/api/answers" \
  -H "X-API-Key: КЛЮЧ_ИЗ_COMPOSE" -d '{"test": true}'
tail ~/survey-kiosk/data/answers.jsonl
```

Ответ 200 и новая строка в файле — приём работает. Неверный ключ вернёт 401.

## Обновление и остановка

```bash
cd ~/survey-kiosk
docker compose up -d --build   # после правок (config.js, docker-compose.yml и т.п.)
docker compose down            # остановить
docker compose logs -f         # логи
```

## Частые вопросы

- **Левая панель пустая / «Вход Alabuga»** — сервис опроса запрещает встраивание в iframe (это его ограничение). Опрос открывается отдельным окном или по QR — это штатный режим.
- **«Браузер заблокировал всплывающие окна»** — разрешите попапы для адреса стойки (шаг 7.2).
- **Ответы не приходят** — проверьте: адрес и ключ в форме интеграции, доступность порта 8080 с сервиса опросов, логи (`docker compose logs api`).
- **«Permission denied» при удалении `data/answers.jsonl`** — старые файлы были созданы контейнером от имени root: `sudo rm -rf ~/survey-kiosk/data` или `sudo chown -R $USER:$USER ~/survey-kiosk/data`. В текущей версии контейнер работает от вашего пользователя, и проблема не возникает (если папку `data` создали вы сами — см. шаг 3.4).
- **После правок страница не обновилась** — обновите версию ассетов в `index.html` (параметр `?v=` у подключений css/js) и пересоберите.
